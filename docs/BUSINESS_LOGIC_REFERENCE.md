## 1. StudentWriteBuffer & Quota Defense Engine

### 1.1 Objective
Eliminate redundant Firestore writes generated by high-frequency student interactions during practice sessions, guaranteeing a **99.7% reduction in cloud database operations**.

### 1.2 Algorithmic State Machine
Implemented in `src/utils/studentWriteBuffer.ts` and `src/utils/syncCoordinator.ts`:

```
                +---------------------------------------+
                |           USER INTERACTION            |
                |  (Answer MCQ / Bookmark / Study Time) |
                +-------------------+-------------------+
                                    |
                                    v
+-----------------------------------------------------------------------+
| 1. INSTANT LOCAL COMMIT (IndexedDB v5)                                |
|    - Update store 'user_progress'                                     |
|    - Update store 'wrong_questions'                                   |
|    - Write telemetry entry to store 'attempt_history'                 |
+-----------------------------------+-----------------------------------+
                                    |
                                    v
+-----------------------------------------------------------------------+
| 2. OUTBOX QUEUING (IndexedDB store: pending_sync_queue)               |
|    - Append or merge mutation event into local outbox                 |
|    - Deduplicate events by questionId (latest state wins)             |
+-----------------------------------+-----------------------------------+
                                    |
                                    v
+-----------------------------------------------------------------------+
| 3. ROUTINE SYNC ELIGIBILITY GATE                                      |
|    canPerformRoutineSync(lastSyncTimestamp):                          |
|    Is (Current_Time - lastSyncTimestamp) >= 24 Hours (86,400,000 ms)?  |
+-----------------+-----------------------------------+-----------------+
                  |                                   |
             NO (Gated)                           YES (Eligible)
                  v                                   v
+-----------------------------------+   +-------------------------------+
| RETAIN IN OUTBOX                  |   | ATOMIC CLOUD FLUSH            |
| - 0 Firestore writes issued       |   | - Read pending mutations      |
| - Student experience is seamless  |   | - Aggregate into single batch |
| - Data is 100% safe in IndexedDB  |   | - Execute single batch write  |
+-----------------------------------+   | - Update sync_metadata time   |
                                        | - Purge local outbox          |
                                        +-------------------------------+
```

### 1.3 Outbox Deduplication Logic
If a student attempts question `q-101` three times in a single day, the buffer collapses the mutations:
$$\text{State}_{\text{final}}(q) = \text{Merge}(\text{State}_1(q), \text{State}_2(q), \text{State}_3(q))$$
- Final `status`, `stage`, and `bookmarked` inherit from the latest attempt.
- `wrongCount` and `timesAttempted` accumulate cumulatively.

## 2. Leitner Spaced Repetition Engine

### 2.1 Theoretical Framework
Implemented in `src/utils/revision.ts`, the spaced repetition system uses a 5-stage Leitner box algorithm ($S_0$ through $S_4$). Practice intervals scale exponentially to transfer knowledge from short-term to permanent memory.

### 2.2 Interval Progression
```typescript
export const INTERVALS = [3, 7, 21, 45, 75]; // Days
```

| Current Stage | Meaning | Interval to Next Review | Next Stage (If Correct) | Next Stage (If Wrong) |
|:---:|:---|:---:|:---:|:---:|
| **Stage 0** | Newly Learned / Reset | $+3$ days | Stage 1 | Stage 0 |
| **Stage 1** | Early Retention | $+7$ days | Stage 2 | Stage 0 |
| **Stage 2** | Intermediate Retention | $+21$ days | Stage 3 | Stage 0 |
| **Stage 3** | Long-Term Retention | $+45$ days | Stage 4 | Stage 0 |
| **Stage 4** | Mastered Knowledge | $+75$ days | Stage 4 (Mastered) | Stage 0 |

### 2.3 Due Today Scheduling Formula
For any question with progress record $P$:
$$\text{isDueToday}(P) \iff \text{FormatDate}(P.\text{nextReviewAt}) \le \text{FormatDate}(\text{Today})$$
- Correct answers advance the question:
  $$\text{Stage}_{n+1} = \min(\text{Stage}_n + 1, 4)$$
  $$\text{NextReviewDate} = \text{Today} + \text{INTERVALS}[\text{Stage}_{n+1}]$$
- Incorrect answers immediately demote the question to reset:
  $$\text{Stage}_{n+1} = 0$$
  $$\text{NextReviewDate} = \text{Today} + \text{INTERVALS}[0] = \text{Today} + 3\text{ days}$$
  $$\text{WrongCount}_{n+1} = \text{WrongCount}_n + 1$$

## 3. RPSC 5th Option 'E' & Evaluation Engine

### 3.1 Examination Evaluation Standard
Implemented in `MCQSessionModal.tsx` and `src/server/liveTestService.ts`, the evaluation engine enforces official Rajasthan Public Service Commission (RPSC) evaluation rules.

### 3.2 Scoring Rubric

$$\text{Final Score} = \sum_{q \in Q} \text{Mark}(q) - \text{Blank Penalty}$$

Where:
$$\text{Mark}(q) = \begin{cases}
+M, & \text{if selectedOption} = \text{correctOption} \quad (0 \le \text{selected} \le 3) \\
-(M \times N), & \text{if selectedOption} \ne \text{correctOption} \quad (0 \le \text{selected} \le 3) \\
0, & \text{if selectedOption} = 4 \quad (\text{Option 'E' — Intentionally Left Blank}) \\
-(M \times N), & \text{if selectedOption} = -1 \quad (\text{Completely Blank / Unbubbled})
\end{cases}$$

- $M$: Marks per question (typically $1.333$ or $2.0$).
- $N$: Negative marking fraction ($0.3333$ for $1/3$ penalty).

### 3.3 Mandatory Bubbling & Disqualification Rule
To prevent OMR tampering, RPSC mandates that every candidate must bubble either an answer (A, B, C, D) or Option 'E'.
$$\text{BlankRatio} = \frac{\sum [q.\text{selectedOption} = -1]}{|Q|}$$
$$\text{isRpscDisqualified} = \begin{cases}
\text{true}, & \text{if BlankRatio} > 0.10 \quad (> 10\% \text{ unbubbled}) \\
\text{false}, & \text{otherwise}
\end{cases}$$
If `isRpscDisqualified == true`, the candidate's scorecard displays an official disqualification notice, and they are omitted from the merit list.

## 4. Smart Priority & Weakness Engine

### 4.1 Weakness Scoring Formula
Implemented in `src/utils/smartPriority.ts`, every question receives an adaptive priority score between $0$ and $100$:

$$\text{PriorityScore} = W_a \cdot (100 - \text{Accuracy}) + W_t \cdot \text{NormalizedTime} + W_r \cdot \text{RecencyFactor}$$

Where:
- $\text{Accuracy} = \frac{\text{CorrectCount}}{\text{AttemptCount}} \times 100\%$
- $\text{NormalizedTime}$: Penalizes hesitation or excessively slow recall.
- $\text{RecencyFactor}$: Weights recently failed questions higher than historical errors.

### 4.2 Special Diagnostic Tags
- **`fast_wrong`:** Response time $< 10$ seconds, but answered incorrectly. Indicates impulsive guessing or a persistent misconception.
- **`slow_recall`:** Answered correctly, but took $> 90$ seconds ($> 2.5\times$ average). Indicates memory struggle.
- **`strong`:** Answered correctly on multiple occasions with response time $< 25$ seconds.

## 6. Multi-Provider AI Rotation & Resilience Engine

### 6.1 Resilience Architecture
Implemented in `src/utils/aiMultiProviderService.ts` and `src/server/cryptoVault.ts`:

```
Incoming AI Request (e.g., OCR extraction or MCQ generation)
                     |
                     v
Select Highest Priority Key with Status == 'available'
                     |
        +------------+------------+
        |                         |
[ Primary: Gemini 2.0 Flash ]     |
        |                         |
     HTTP 200 OK                  | HTTP 429 (Rate Limit) / 503
        |                         v
     Success            1. Mark Key Status: 'rate_limited'
                        2. Set Cooldown: Now + 5 Minutes
                        3. Route to Next Provider in Priority Chain
                                  |
                                  v
                        [ Secondary: Claude 3.5 Sonnet ]
                                  |
                        [ Fallback: OpenAI GPT-4o / Groq ]
```

### 6.2 Health States
- **`available`:** Key is operational and ready to receive prompts.
- **`rate_limited`:** Returned HTTP 429; placed in automatic cooldown.
- **`quota_exhausted`:** Billing or daily limit exceeded; disabled until reset.
- **`auth_failed`:** Invalid API key; disabled and flagged for admin review.
